# Adaptive-IoT-Vibration-Monitor

**Energy-aware adaptive IoT vibration sensing using edge intelligence**

A research project combining an ESP32 vibration-monitoring workflow, an interactive web portal, and the **DSRA-PMLO** Python signal-sampling package.

> **Important:** Browser simulation values are generated examples, not measurements from hardware. The **Results** page displays data only after you import CSV logs from your own experiments.

## Overview

The **Adaptive-IoT-Vibration-Monitor** explores energy-aware IoT sensing by combining vibration monitoring with adaptive sampling and edge-oriented processing.

The project contains three related parts:

1. **Interactive web portal** — project documentation, a browser-based educational simulation, experiment planning, and CSV results exploration.
2. **Python DSRA-PMLO workflow** — adaptive sample selection, parameter optimization, signal reconstruction, evaluation, and Matplotlib visualization.
3. **ESP32-oriented sensing workflow** — implementation guidance for vibration sensing and future connection to physical hardware.

It is intended for research, experimentation, education, and evaluation of adaptive IoT sampling techniques.

## System Architecture

The intended data flow is:

```text
Vibration source
      |
      v
 MPU6050 ---> ESP32 adaptive sensing ---> MQTT ---> Edge processing
                                                    |
                                                    v
                                         Logs and evaluation
                                                    |
                                                    v
                                         Web Results explorer
```

The Python DSRA-PMLO workflow supports offline sample selection and reconstruction from recorded data. The browser simulation illustrates the concepts with generated values; it does not connect to physical hardware by itself.

## Python Workflow

The Python package is located in:

```text
src/dsra_pmlo/
```

The workflow supports:

- Choosing an input data file and target column
- Automated or manual E and S parameter search
- Signal reconstruction and test-set evaluation
- Reporting reconstruction error and sampling reduction
- Matplotlib visualization of search and reconstruction results

The recommended package entry point is:

```bash
python -m dsra_pmlo.use_case
```

> Do not run `base.py`, `automated.py`, or `manual.py` directly. They are package modules; run the package entry point instead.

### Configuration

Edit the configuration in:

```text
src/dsra_pmlo/use_case.py
```

Select the input file, target column, and mode (`"automated"` or `"manual"`). The default configuration uses:

```text
File:       src/dsra_pmlo/data/downsampled_data_20000.txt
Target:     Amplitude
Mode:       automated
```

The standard workflow reserves the first 40% of the loaded signal for testing and uses the remaining 60% for training.

## Datasets and Results

### Included datasets

Datasets are stored in `src/dsra_pmlo/data/`:

| File | Description |
|---|---|
| `motor_no_load.txt` | Motor signal without load |
| `motor_light_load_brb.txt` | Motor signal with a light-load broken-rotor-bar condition |
| `motor_no_load_brb.txt` | Motor signal with a no-load broken-rotor-bar condition |
| `downsampled_data_20000.txt` | 20,000-sample downsampled reference signal |
| `synthetic_data.txt` | Synthetic signal |

The bundled DSRA-PMLO datasets use `Amplitude` as the numeric target column. The downsampled reference also contains a `Time` column in seconds.

### Experimental CSV format

The Results page accepts CSV files with supported columns such as:

```csv
timestamp,vibration,sampling_rate,transmission_rate,processing_rate,packets_sent,energy,detection,latency
1678886400000,0.45,100,10,50,1,15.2,0,0
```

CSV files are parsed locally in the browser. The imported values are visualized from the selected file; the page does not invent results when no CSV has been loaded.

### Experimental data policy

Keep simulated, synthetic, and example data separate from physical measurements. Retain original hardware logs alongside processed results to support reproducibility.

## Installation

### Web portal

The web portal requires Node.js. The `package.json` declares **pnpm** as the package manager.

```bash
pnpm install
```

The Python package requires Python 3.8 or newer. Dependencies, including NumPy, SciPy, pandas, and Matplotlib, are declared in `pyproject.toml`.

#### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

## Hardware and Live Streaming

The sensing workflow is designed around an ESP32 and vibration sensor, with MQTT communication and optional energy measurement hardware.

The browser simulation does **not** connect to physical hardware by itself. Live sensor streaming requires:

- A configured ESP32 sensing device
- An MQTT broker and/or WebSocket bridge
- A data transport and backend integration
- A connection from that integration to the web portal

Actual energy, latency, and detection results must be measured from physical experiments; the browser demo only generates educational model values.
